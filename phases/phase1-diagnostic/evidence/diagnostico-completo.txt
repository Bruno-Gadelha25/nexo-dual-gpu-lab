GPU GTX 970 (PCI bus 1, device 0, function 0):

GPU GTX 750 Ti (PCI bus 2, device 0, function 0):
- PnP parent/root port: Intel VEN_8086 DEV_0155, caminho PCIROOT(0)#PCI(0101)#PCI(0000), ACPI PEG1.
- PnP: velocidade atual 1; largura atual x8; velocidade máxima do endpoint 3; largura máxima x16.
- nvidia-smi: link atual Gen1 x8; gen.max=1, gpumax=3, hostmax=1; width.max=x16.

Interpretação e divergência:
- O link NEGOCIADO/ATUAL foi observado em Gen1 x8 para ambas as placas naquele momento. Não confundir com capacidade máxima.
- O PnP informa máximo de endpoint Gen3 x16, enquanto nvidia-smi informa GPU max Gen3, mas hostmax/gen.max 1. A especificação da CPU e da placa-mãe declara PCIe 3.0 e modos x16, x8/x8 ou x8+x4+x4. As ferramentas discordam sobre máximo do host; portanto, máximo negociado efetivo da plataforma e motivo do Gen1 atual NÃO CONFIRMADOS. Não se alterou BIOS/energia nem se provocou carga para reavaliar o estado do link.
- Topologia PEG0/PEG1 aponta dois caminhos PCIe separados, mas o mapeamento desses caminhos para os rótulos físicos dos slots da placa não pôde ser confirmado por software. Não se afirma qual placa está no slot físico PCIEX16 ou PCIEX8.
- Limites teóricos conforme manual da placa: primeiro slot até x16; ao ocupar PCIEX8, primeiro slot passa a até x8; se PCIEX4 também ocupado (disponível com Ivy Bridge), o primeiro fica até x8 e PCIEX8 até x4. O i7-3770K aceita até 2x8 ou x8+2x4. Nada disso substitui o estado observado Gen1 x8.

Não se usou teste de carga; nenhuma alteração de hardware ou configuração foi feita.

IDs PnP completos: GTX970 VEN_10DE DEV_13C2 SUBSYS_85081043 REV_A1; GTX750Ti VEN_10DE DEV_1380 SUBSYS_105F10DE REV_A2. WMI reporta AdapterRAM 4,293,918,720 bytes nas duas (campo aproximado/legado); NVSMI confirma 4096 MiB em ambas. DXDiag reporta memória dedicada disponível ao sistema 4030 MB / 4044 MB e 16364 MB compartilhada em cada uma; DXGI reporta alocações dedicadas ~4.23 GB e memória de sistema compartilhada ~17.16 GB. Os campos representam métricas e unidades diferentes e a memória compartilhada não é VRAM adicional equivalente.

Arquitetura: Maxwell (GTX970 GM204, compute 5.2; GTX750 Ti GM107, compute 5.0 conforme NVSMI). As duas GPUs são dispositivos CUDA distintos e permanecem enumeráveis ao mesmo tempo.
Teste CUDA: foi compilado teste C++ pequeno que carrega nvcuda.dll do driver (já presente), chama cuInit(0), cuDeviceGetCount e consultas de nome, compute capability e memória. Resultado: cuInit=0; contagem=2; GPU0 GTX970 5.2 / 4095 MiB; GPU1 GTX750 Ti 5.0 / 4095 MiB. Nenhum kernel foi executado.

Toolkit/runtime:
- nvcuda.dll existe em C:\Windows\System32; isso é a API de driver CUDA fornecida pelo driver NVIDIA.
- nvcc e diretório padrão NVIDIA GPU Computing Toolkit\CUDA não encontrados; CUDA_PATH vazio. Não foi identificado CUDA Toolkit instalável/local para compilar kernels.
- nvidia-smi informa “CUDA Version 13.0”: versão máxima da interface CUDA compatível com o driver, não prova presença de Toolkit 13 nem de cudart.
- Python Torch instalado é CPU-only (torch.version.cuda=None, torch.cuda.is_available=False); portanto não é um caminho CUDA funcional nesta instalação.
- NVIDIA documenta geração de código nativo Maxwell para compute 5.0 desde CUDA Toolkit 6.0 e para 5.2 desde Toolkit 6.5. O suporte atual de versões precisa ser escolhido com base nas release notes/toolchain efetivamente instalada; CUDA 13.0 Update 1 removeu suporte a Maxwell em certos componentes/targets (a nota de release é específica, não prova que toda API CUDA 13 foi removida). Sem toolkit instalado, versão de compilação compatível não foi testada.

SLI/NVLink/memória unificada: não detectados nem presumidos. A enumeração CUDA simultânea não agrega VRAM nem divide automaticamente o trabalho.
